# Run Arbitrary SQL Scripts

## Description

This playbook runs arbitrary SQL scripts against an Oracle database using the `oracle_sql` module. A single script or multiple scripts can be run, in the order listed.

In the example below, two scripts are run: one creates a simple table and the other inserts a few rows into it.

> **Migration note:** This collection has been migrated from `cx_Oracle` to `python-oracledb` (thin mode).
> Thin mode is pure Python — no Oracle Instant Client is required on the control node.
> All database connections are made over TCP from `localhost` directly to the database listener.
> The `oracle_db_home` variable is no longer needed.
> Script files are read from the Ansible control node, not from the AIX LPAR.

---

## Files to Update

| File | Purpose |
|------|---------|
| `playbooks/vars/manage-arbitrarysql-vars.yml` | DB hostname, service name, listener port, list of SQL scripts |
| `playbooks/vars/vault.yml` | SYS password (SYSDBA connect) — **encrypt with ansible-vault** |

---

## Step 1 — Create the SQL Scripts

Create the scripts on the control node. Relative paths are resolved from the directory where `ansible-playbook` is run, so absolute paths are recommended.

`create.sql`
```sql
CREATE TABLE ansible1(person_id NUMBER GENERATED BY DEFAULT AS IDENTITY, first_name VARCHAR2(50) NOT NULL,last_name VARCHAR2(50) NOT NULL);
insert into ansible1 (person_id,first_name,last_name) values (10,'ansiuser','2');
```

`insert.sql`
```sql
insert into ansible1 (person_id,first_name,last_name) values (11,'Ansi','User');
insert into ansible1 (person_id,first_name,last_name) values (12,'Ansi1','User1');
```

---

## Step 2 — Update `manage-arbitrarysql-vars.yml`

```yaml
# Run Arbitrary SQL Scripts - Variables section
hostname: ansible-db                        # AIX LPAR hostname where the database is running (TCP endpoint).
listener_port: 1521                         # Database listener port.
service_name: prodpdb                       # Database service name to connect to as SYSDBA.
# oracle_db_home not needed — oracle_sql module uses Thin mode (pure Python, no Oracle client required)

sqlfile:                                    # Scripts are read from the Ansible control node and run in the order listed.
- { script: 'create.sql' }                  # SQL Script 1 location & name of the file.
- { script: 'insert.sql' }                  # SQL Script 2 location & name of the file.
```

---

## Step 3 — Update `vault.yml`

```yaml
default_dbpass: Oracle4u    # SYS password used to connect as SYSDBA.
```

---

## Step 4 — Encrypt the Vault File

```bash
ansible-vault encrypt vars/vault.yml
```

```
New Vault password:
Confirm New Vault password:
Encryption successful
```

---

## Step 5 — Review the Playbook

```yaml
# playbooks/manage-arbitrarysql.yml
- name: Run Arbitrary SQL Scripts
  hosts: localhost
  gather_facts: false
  vars_files:
   - vars/vault.yml
   - vars/manage-arbitrarysql-vars.yml
  roles:
     - { role: oradb_manage_sql }
```

---

## Step 6 — Execute the Playbook

```bash
ansible-playbook -i playbooks/inventory.yml playbooks/manage-arbitrarysql.yml --ask-vault-pass
```

## Step 7 — SQL Verification

Connect to the database and verify directly:

```sql
-- Confirm the rows were inserted
SELECT person_id, first_name, last_name
FROM ansible1
ORDER BY person_id;
```

The table is created in the schema of the connecting user (`SYS`). To remove it after testing:

```sql
DROP TABLE ansible1 PURGE;
```

## Variables Reference

| Variable | File | Description |
|----------|------|-------------|
| `hostname` | `manage-arbitrarysql-vars.yml` | AIX LPAR hostname (TCP endpoint for DB connection) |
| `listener_port` | `manage-arbitrarysql-vars.yml` | Database listener port (default: 1521) |
| `service_name` | `manage-arbitrarysql-vars.yml` | Database service name to connect to as SYSDBA |
| `sqlfile` | `manage-arbitrarysql-vars.yml` | List of `{ script: '<path>' }` entries, read from the control node and run in order |
| `default_dbpass` | `vault.yml` | SYS password used to connect as SYSDBA |
| `db_user` | role defaults | Connecting user (default: `sys`) |
| `db_mode` | role defaults | Connection mode (default: `sysdba`) |
